# Provider verb matrix

What each maintained adapter can do for the provider-dependent verbs
([provider-verbs.md](provider-verbs.md)), and what backs each claim. Two
things are kept apart:

- **Capability**: whether the adapter's descriptor declares the verb.
  This is the adapter's own statement, read from this build.
- **Maturity**: how far the adapter's author says it is proven. Every
  adapter in this release is `experimental`, whatever it declares.

A declared verb is not a promise: the provider account, the channel's
configuration and the provider's rules decide whether it works right now
(`heo channel check --remote`).

Some adapters declare more than heo serves. `google.mail`,
`microsoft.mail` and `imap.mail` declare the conversation-state
capabilities `archive`, `move`, `read_state`, `flag` and `trash`, and
`slack.chat` and `discord.chat` declare `archive`. heo has no verb for
them yet, so they have no row below: declared by the adapter, not
served by heo. `TestDeclaredCapabilitiesPerAdapter` pins them.

## How to read it

| Column | Meaning |
| --- | --- |
| Declared | the adapter's descriptor enables the verb; pinned for every adapter by `TestDeclaredVerbsPerAdapter`, and the declarations themselves (capabilities, extension effects with the capability each needs) by `TestDeclaredCapabilitiesPerAdapter`, so a uma change that enables no verb is reviewed too |
| Tested by | the Go tests that back the row, or `none`; *(check only)* marks a test that checks a declaration or that a channel starts and runs no verb |
| Recorded against | where the tests ran the verb: `real private sandbox` (cassettes recorded against an account the maintainers own, replayed on every `go test`), `real live account, 2 sends` (the same, against a live account that reaches a person, with a hard cap on what the recording sent), `fake provider` (heo's own fake adapter), `in-process` (the real adapter with no provider reached: answered by a scripted stand-in of the provider's API, queued and never sent, or none to reach), `none` |
| Maturity | the descriptor's |

For a verb the adapter does **not** declare, the row is the refusal: heo
answers `UNSUPPORTED` at the preview and again on submission, before
anything is written. The tests cited run that refusal on the fake
provider, which declares nothing; the adapter's own declaration is the
pinned `Declared` column. A refusal that is configuration, not
declaration (`github.issues` with `replies` off) is a different state,
`config`, shown by `heo channel get` and recorded in the GitHub cassettes.

No row claims more than its tests. The package that renders this page
fails its tests when a row cites a test that does not exist, when a row
says it was recorded against something its tests were not, and when a
declared verb has no entry; the page is regenerated by `make docs-gen`
and `make docs-check` fails when it is stale.

## What is not in the table

  variants) are not rows: they are test fixtures, not adapters you
  configure.
- `github.issues` is recorded through the real `heo` binary. Its inbound
  side (issues and comments arriving) is replayed from webhook payloads
  written from real answers; no public webhook URL was ever exposed to
  record it. Re-recording is in
  [DEVELOPING.md](../DEVELOPING.md#recording-github-issues).
- `twilio.sms` is recorded through the real `heo` binary against a live
  Twilio account: two texts, both to the maintainer's own phone, and one text
  to a number too short to exist, which Twilio rejects without creating
  a message. The account is live, not a sandbox, so the recording is capped at
  two sends ever and reaches nothing but its own messages. Incoming texts
  and the status callback are replayed from unsigned fixtures the test
  signs; no public webhook URL was exposed. Re-recording is in
  [DEVELOPING.md](../DEVELOPING.md#recording-twilio-sms).
- Twilio WhatsApp, Zendesk and Meta WhatsApp have no cassettes yet; the
  status list above says what each recording needs. The Twilio account
  has no WhatsApp sender, so the `twilio.sms` sends do not cover
  `twilio.whatsapp`.
- A capability that enables no heo verb is not a column.
  `github.issues`, `google.mail` and `microsoft.mail` declare
  `extension_execute` for effects of their own (`github.issues.update`,
  `google.mail.labels`, `microsoft.mail.categories`); heo registers none
  of them and has no verb for them, so their `ticket transition` row is
  the refusal: that verb is Zendesk's ticket update alone. The status

  run in process; for every other adapter the two participant rows are
  refusals only. The adapters that declare `receipt`
  (`native.webwidget`) and `history` (`github.issues`, `twilio.sms`,
  `slack.chat`, `discord.chat`) are

  the preview, which reads their real declaration and imports nothing. The
  receipt and history verbs are run end to end only on heo's
  own fake provider, which is not a row; see
  [provider-verbs.md](provider-verbs.md).
